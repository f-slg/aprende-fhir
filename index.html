    Aprende FHIR desde cero

    Taller práctico de HL7 FHIR R4 con un caso clínico ecuatoriano

    Abrir el sitio web del taller

    Empezar · Módulos · El caso · Validar

    Un recorrido para aprender FHIR haciendo, paso a paso: crearás, buscarás, corregirás y enlazarás 36 tipos de recursos siguiendo a un mismo paciente, desde su primera consulta hasta el resumen internacional (IPS) que lleva de viaje.

    En cada módulo:

    • una ficha de cada recurso: qué es, para qué se usa, cuándo usar otro y sus elementos principales, con la cardinalidad y el tipo tomados de la especificación oficial;
    • la construcción paso a paso: del recurso mínimo al completo, campo por campo, explicando cada decisión (todas las versiones intermedias son válidas);
    • errores a propósito, con la respuesta real del servidor, para aprender a leerlos;

    • autoevaluación y resumen.

    • Para quién: profesionales de salud, epidemiólogos, estudiantes y equipos técnicos que se acercan por primera vez a FHIR. No hace falta saber programar.

    • Tres formas de practicar con el mismo contenido: Postman, R/RStudio o curl.
    • Recursos validados: las 80 soluciones y sus 133 versiones intermedias se revisan con el validador oficial de HL7 en cada cambio, y el taller completo se ejecuta en un servidor HAPI FHIR.

    Solo datos ficticios. Las personas, las cédulas (empiezan con 99, un código de provincia que no existe) y los establecimientos son inventados. Si usas un servidor público, todo lo que envíes será visible para cualquiera: nunca subas datos reales de pacientes.

    Elige tu camino¶

    Ideal si... Cómo empezar
    Postman Es tu primera vez con FHIR o no programas. Ves cada petición y cada respuesta. Instala Postman, importa postman/aprende-fhir.postman_collection.json y ejecuta las peticiones en orden. Cada POST guarda el id creado para las siguientes.
    R / RStudio Trabajas con datos y quieres convertir los resultados en tablas. Abre aprende-fhir.Rproj, instala httr2 y jsonlite, y sigue r/primeros_pasos.R. Con source("r/taller.R") ejecutas todo.
    curl Prefieres la terminal o quieres automatizar. curl/taller.sh ejecuta todo el taller; curl/taller.sh 05 solo hasta el módulo 05. Requiere curl y jq.

    Los tres caminos usan los mismos archivos JSON y la misma lista de pasos (herramientas/pasos.json).

    Los servidores¶

    Por defecto se usa el servidor público de HAPI FHIR: https://hapi.fhir.org/baseR4 (variable FHIRURL). El módulo 18 usa además el servidor de terminología de HL7, https://tx.fhir.org/r4 (variable TXURL). Para cambiarlos, edita las variables en Postman, o en R y curl:

    FHIRURL=http://localhost:8080/fhir curl/taller.sh

    Si tienes Docker o Podman puedes levantar tu propio servidor en un minuto:

    docker run -p 8080:8080 hapiproject/hapi:latest

    y usar http://localhost:8080/fhir.

    Desde VS Code con Postman¶

    El repositorio viene preconfigurado para VS Code. Ábrelo con code aprende-fhir y acepta instalar las extensiones recomendadas (Postman, R, vista previa de Mermaid y herramientas FHIR).

    1. En la barra lateral, abre Postman e inicia sesión (la extensión usa tu cuenta de Postman, la gratuita basta).
    2. Import (icono de la barra de título del panel, o Ctrl+Mayús+P → Postman: Import). El botón aparece después de iniciar sesión y elegir un workspace. La extensión rechaza colecciones grandes, así que importa las tres partes de postman/niveles/ en lugar de la colección completa: 1-basico, 2-intermedio y 3-avanzado.
    3. Importa también un entorno de la carpeta postman/:
    4. hapi-publico.postman_environment.json: servidor público de HAPI.
    5. hapi-local.postman_environment.json: tu HAPI en http://localhost:8080/fhir.
    6. Selecciona el entorno arriba a la derecha y ejecuta las peticiones en orden con Send. Cada POST guarda el id en el entorno seleccionado, así que los módulos siguientes (aunque estén en otra parte) ya lo encuentran. Para correrla entera, usa Run sobre la colección.

    Con el README del módulo abierto a un lado (vista previa: Ctrl+Shift+V) y Postman al otro, sigues la explicación y ejecutas cada paso sin salir del editor.

    En Terminal → Ejecutar tarea… tienes atajos para lo demás:

    Tarea Qué hace
    HAPI local: iniciar / detener Levanta o detiene un HAPI FHIR con Podman o Docker y espera a que responda
    Taller: ejecutar la colección de Postman (newman) Corre la colección completa desde la terminal y muestra qué paso falla
    Taller: ejecutar con curl curl/taller.sh, todo o hasta el módulo que elijas
    Taller: ejecutar con R r/taller.R, todo o hasta el módulo que elijas
    Validar con el validador oficial de HL7 herramientas/validar.sh
    Actualizar pasos, fichas y colección de Postman herramientas/actualizar.py
    Sitio web: vista previa El sitio en http://127.0.0.1:8000

    El caso¶

    Luis Alberto Paredes Cevallos, 46 años, nacido en Riobamba y residente en Quito, consulta en el Hospital General Docente Ejemplo por dolor abdominal, náuseas y diarrea. La Dra. Andrea Salazar diagnostica una intoxicación alimentaria y, en la anamnesis, registra su alergia a la penicilina, el losartán que toma por hipertensión y un dato importante: su madre tuvo cáncer de mama. Como Luis tiene fiebre, las vacunas se difieren; dos semanas después recibe la de la influenza y el refuerzo de Td.

    En abril, Luis se palpa un nódulo en la mama izquierda. La ecografía es sospechosa y una biopsia confirma un carcinoma ductal infiltrante con receptor de estrógeno positivo. El comité de tumores define el plan: cirugía, quimioterapia con doxorrubicina y hormonoterapia con tamoxifeno. Los cuestionarios de seguimiento muestran que el tamoxifeno le provoca sofocos y dolor articular, y se suspende. En febrero de 2026, antes de viajar, Luis recibe su resumen internacional del paciente (IPS).

    03-abr-2025 Vacunatorio: influenza y Td 08
    22 a 28-abr-2025 Nódulo en la mama: ecografía BI-RADS 4, orden de biopsia y derivación a oncología 10
    06 a 13-may-2025 Biopsia, informe de patología y diagnóstico de cáncer 11

    Validar tus recursos¶

    Cuando escribas tus propias soluciones, valídalas con el validador oficial de HL7. Necesitas tener Java instalado:

    herramientas/validar.sh

    El script descarga el validador la primera vez y valida contra FHIR R4 (estructura, cardinalidades, reglas y códigos LOINC, SNOMED CT, CIE-10 y CVX) todas las soluciones y versiones intermedias. Además comprueba que el validador detecte cada error a propósito, y valida contra el perfil del taller (módulo 18) y contra la guía oficial IPS (módulo 19). Agrega --avisos al final para ver también las advertencias. También puedes validar un recurso suelto en https://validator.fhir.org/.

    Preguntas frecuentes¶

    ¿Por qué el servidor aceptó un recurso con errores? Muchos servidores no validan todo al guardar: descartan elementos desconocidos o aceptan recursos a los que les falta algo obligatorio. El módulo 01 lo explica y cada módulo tiene un error a propósito de cada tipo. Valida siempre tus recursos.

    ¿Por qué aparece varias veces el mismo paciente? Cada POST crea un recurso nuevo. Si ejecutas el taller dos veces, tendrás dos "Luis". Es un buen motivo para conocer la creación condicional del módulo 03.

    ¿Los códigos son reales? Sí. LOINC, SNOMED CT, CIE-10 y UCUM son las terminologías reales, y el validador revisa cada código y su nombre. Lo ficticio son las personas, los identificadores y los establecimientos.

    ¿Los system de los identificadores son oficiales? No. Usamos direcciones didácticas (https://f-slg.github.io/aprende-fhir/sid/...). En un proyecto real se usan las que defina la guía de implementación nacional.

    Estructura del repositorio¶

    modulos/NN-tema/README.md       explicación, ejercicios y pistas
modulos/NN-tema/soluciones/     recursos FHIR de solución (JSON)
modulos/NN-tema/pasos/          versiones intermedias de la construcción paso a paso
modulos/NN-tema/errores/        errores a propósito
postman/                        colección completa y entornos de Postman (público y local)
postman/niveles/                la misma colección en tres partes (básico, intermedio, avanzado)
.vscode/                        tareas y extensiones recomendadas para VS Code
r/                              funciones y scripts para R/RStudio
curl/                           script para la terminal
herramientas/pasos.json         lista ordenada de pasos del taller (y errores esperados)
herramientas/construccion.json  qué campos agrega cada paso de la construcción
herramientas/actualizar.py      genera los pasos, las fichas y Postman
herramientas/validar.sh         validación con el validador oficial de HL7
herramientas/sitio/             sitio web (MkDocs Material) a partir de los README

    El sitio web (https://f-slg.github.io/aprende-fhir/) se arma con los mismos README y se publica solo en cada cambio. Para verlo en tu equipo: pip install -r herramientas/sitio/requisitos.txt y python3 herramientas/sitio/construir.py --servir.

    Si cambias una solución, un paso o un README, ejecuta python3 herramientas/actualizar.py: regenera las versiones intermedias, rellena en los README las fichas (con la cardinalidad y el tipo de la especificación oficial) y los bloques de cada paso, y actualiza la colección de Postman. Después, valida con herramientas/validar.sh.
